## 缓存策略

### 缓存目录结构

```
data/.cache/
├── version.json              # 版本信息
│   {
│     "version": "5.4.3",
│     "lastUpdated": "2025-01-31T10:00:00Z",
│     "source": "official"
│   }
│
├── metadata.json             # 元数据索引
│   {
│     "optionCount": 52,
│     "categories": {
│       "global": [...],
│       "box": [...],
│       "regular": [...]
│     }
│   }
│
├── option.{ext}              # 选项树（压缩后）
├── type.{ext}                # 类型定义（压缩后）
│
└── options/                  # 单个选项详情
    ├── title.json            # 或 .zip / .br / .mp
    ├── legend.json
    ├── series-line.json
    └── ...
```

### 缓存策略

1. **Cache First**: 优先从缓存读取，不存在才请求远程
2. **Force Update**: `--force` 参数可跳过缓存，强制更新
3. **Version Check**: 对比远程版本和本地版本，支持增量更新
4. **压缩选项**: 支持 none/zip/brotli/msgpack，默认 none

## 并发控制

### 下载器配置

```typescript
interface BatchOptions {
  concurrency: number;      // 并发数，默认 6
  retryCount: number;       // 重试次数，默认 3
  retryDelay: number;       // 重试延迟，默认 1000ms
  timeout: number;          // 超时时间，默认 30000ms
}
```

## 错误处理策略

### 下载错误

1. **网络超时**: 自动重试，最多 3 次
2. **404 错误**: 记录错误，跳过该选项
3. **解析错误**: 记录错误，使用原始数据
4. **磁盘错误**: 抛出异常，终止流程

### 错误回调

```typescript
interface FetchError {
  phase: 'metadata' | 'download' | 'parse' | 'save';
  item?: string;           // 出错的具体选项
  error: Error;
  retryCount: number;      // 已重试次数
}

fetcher.onError((error: FetchError) => {
  console.error(`[${error.phase}] ${error.item}: ${error.error.message}`);
});
```

## 性能考虑

### 1. 并发下载
- 默认并发 6，避免请求过多被限制
- 支持配置，根据网络环境调整

### 2. 压缩存储
- 默认 none，开发环境便于调试
- 生产环境可使用 zip 减少存储空间

### 3. 增量更新
- 仅下载变更的选项
- 减少不必要的网络请求

### 4. 流式处理
- `fetchOptionsBatch` 返回 AsyncGenerator
- 支持边下载边处理，减少内存占用

## 安全考虑

### 1. 沙箱解析
- 使用 `new Function()` 解析 ECharts JS 数据
- 创建空 `window` 对象避免污染全局

### 2. 输入验证
- 验证下载数据的完整性
- 校验解析后的数据结构

### 3. 错误隔离
- 单个选项失败不影响整体流程
- 错误详细记录，便于排查
