# ECharts Vario Schema - 架构文档

## 系统架构概览

本项目是一个将 Apache ECharts 官方文档转换为 Vario-Vue Schema 的完整解决方案。

## 核心组件

### 1. Fetcher (packages/fetcher)

**职责**: 从 ECharts 官网获取原始物料数据

**核心类**:
- `EChartsFetcher` - 主获取器
- `ConcurrentDownloader` - 并发下载器
- `CacheManager` - 缓存管理器
- `DataCompressor` - 数据压缩器

**数据流**:
```
ECharts API → Downloader → Parser → Cache → Compressor
```

### 2. Core (packages/core)

**职责**: 将原始数据转换为 Vario-Vue Schema

**核心类**:
- `BaseLoader` - 加载基础数据
- `TypeAnalyzer` - 类型分析器
- `SchemaGenerator` - Schema 生成器

**数据流**:
```
Cache → Loader → Analyzer → Generator → Schema JSON
```

### 3. Smart Components (packages/smart-components)

**职责**: 提供智能表单组件

**组件列表**:
- `SmartColorInput` - 颜色输入（支持关键字）
- `SmartNumberInput` - 数字输入（支持特殊值）
- `SmartOpacityInput` - 透明度输入
- `SmartPositionInput` - 位置输入
- `SmartSizeInput` - 尺寸输入
- `SmartStyleSelect` - 样式选择
- `SmartUnionInput` - 联合类型输入

### 4. CLI (packages/cli)

**职责**: 提供命令行工具

**命令**:
- `fetch` - 获取基础数据
- `fetch --all` - 批量获取所有选项
- `check-update` - 检查更新

### 5. Studio (apps/studio)

**职责**: 可视化控制台

**页面**:
- Dashboard - 概览面板
- Materials - 物料管理
- Parser - 解析器配置
- Preview - 实时预览
- Generator - 批量生成

## 数据模型

### ECharts 原始数据

```typescript
// 选项树（大纲）
interface OptionOutline {
  [key: string]: OptionNode;
}

interface OptionNode {
  type: 'option' | 'component';
  children?: OptionNode[];
}

// 类型定义
interface TypeTree {
  [key: string]: TypeDefinition;
}

interface TypeDefinition {
  type: string | string[];
  default?: any;
  desc?: string;
  isObject?: boolean;
  isArray?: boolean;
}
```

### Vario-Vue Schema

```typescript
interface VarioSchema {
  type: string;           // 组件类型
  _label: string;         // 中文标签
  _tips?: string;         // 提示信息
  props: {
    modelValue: {
      path: string;       // 数据路径
      value: any;         // 默认值
      type?: string;      // 值类型
    };
    // 其他组件属性
  };
  children?: VarioSchema[];  // 子组件
}
```

## 缓存策略

### 缓存结构

```
data/.cache/
├── version.json          # 版本信息
├── metadata.json         # 元数据
├── option.mjs            # 选项树（或压缩版本）
├── type.mjs              # 类型定义（或压缩版本）
└── options/
    ├── title.mjs         # 单个选项详情
    ├── legend.mjs
    └── ...
```

### 缓存键设计

```typescript
interface CacheKey {
  type: 'base' | 'option';
  key?: string;           // 对于 option 类型
  version?: string;       // ECharts 版本
  timestamp: number;      // 缓存时间
}
```

## 压缩策略

支持三种压缩模式：

| 模式 | 扩展名 | 库 | 适用场景 |
|------|--------|-----|---------|
| none | .mjs | - | 开发调试 |
| zip | .zip | fflate | 平衡压缩率和速度 |
| brotli | .br | zlib | 最大压缩率 |
| buffer | .bin | msgpack5 | 二进制存储 |

## 并发策略

### 下载并发控制

```typescript
const DEFAULT_BATCH_OPTIONS = {
  concurrency: 6,         // 同时下载 6 个
  retryCount: 3,          // 失败重试 3 次
  retryDelay: 1000,       // 重试间隔 1 秒
  timeout: 30000,         // 超时 30 秒
};
```

### 队列管理

使用异步生成器实现背压控制：

```typescript
async function* fetchBatch(keys: string[]): AsyncGenerator<FetchResult> {
  const queue = new PQueue({ concurrency: 6 });
  
  for (const key of keys) {
    yield queue.add(() => fetchSingle(key));
  }
}
```

```typescript
function calculateRetryDelay(attempt: number, baseDelay: number): number {

}
```

## 性能优化

### 1. 缓存优先

所有数据优先从缓存读取，仅在必要时请求远程 API。

### 2. 并发下载

使用异步队列控制并发数，避免请求过多被限制。

### 3. 增量更新

通过版本对比实现增量更新，减少不必要的数据传输。

### 4. 压缩存储

支持多种压缩算法，减少存储空间和 I/O 时间。

## 安全考虑

### 1. 沙箱执行

解析 JavaScript 数据时使用 Function 构造器创建沙箱环境：

```typescript
function safeParse(jsCode: string): any {
  const fn = new Function('window', `return ${jsCode}`);
  return fn({});  // 传入空对象作为 window
}
```

### 2. 路径安全

所有文件操作使用绝对路径，防止目录遍历攻击。

### 3. 输入验证

验证所有用户输入，防止注入攻击。
